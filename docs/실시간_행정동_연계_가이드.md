# 실시간 데이터 → 행정동 연계 가이드

## 목적
서울 실시간 도시데이터(citydata)는 **spot(주요장소 121곳, `AREA_NM`/`AREA_CD`)** 단위.
backtest_data 의 통합 키는 **행정동(8자리 `adstr_cd`)**. 둘을 맞춰야 과거 학습 모델과
실시간 신호를 결합해 "입지 입력 → 추천메뉴 + 예상매출"을 리얼타임 서빙할 수 있다.

## 파이프라인
```
[GitHub Actions 매시간 수집]  collect_realtime.py
        ↓  raw/realtime/{cmrcl,ppltn,cmrcl_rsb,...}/{YYYY-MM-DD}.csv
[spot→행정동 매핑]            scripts/spot_to_dong.py  →  scripts/spot_to_dong.csv
        ↓
[행정동 일자 집계]            scripts/realtime_to_dong.py
        ↓  processed/realtime_dong_daily.parquet       (행정동 × 일자)
           processed/realtime_dong_cat_daily.parquet   (행정동 × 업종 × 일자)
[모델 서빙/재학습]            일자 입지×업종 모델(xgb_location_daily)에 실시간 피처로 결합
```

## 1) 매핑 — scripts/spot_to_dong.py
- 121개 spot → 대표 행정동(`adstr_cd`). 코드는 실데이터 행정동 목록으로 검증(잘못된 코드 방지).
- `conf` 컬럼: high(상권·역세권=서비스 핵심) / mid·low(공원·문화=검수 권장).
- 서울대공원은 과천시라 제외(서울 행정동 없음).
- **정밀화**: 공식 핫스팟 좌표(위경도)가 확보되면 행정동 경계와 point-in-polygon 으로 자동 갱신 권장.

## 2) 집계 — scripts/realtime_to_dong.py
- `cmrcl`  → 행정동×일자: `rt_cmrcl_lvl`(혼잡도), `rt_pay_cnt`/`rt_pay_amt`(실시간 결제=매출 프록시),
  결제자 성별·연령·개인비율.
- `ppltn`  → 행정동×일자: `rt_ppltn`(실시간 인구), `rt_congest`.
- `cmrcl_rsb` → 행정동×**업종**×일자: `rt_rsb_pay_amt`/`rt_rsb_pay_cnt`/`rt_rsb_mct_cnt`
  (RSB 중분류를 푸드트럭 적합 10업종으로 매핑) — **업종별 실시간 수요 신호**.
- 한 행정동에 여러 spot/여러 시각 → 평균 집계. 키는 `adstr_cd`(8자리)로 backtest 와 동일.

## 3) 모델 연계 (다음 단계)
- 서빙 시: 행정동의 (과거 구조 피처 + 그 날짜의 실시간 `rt_*` 피처)로 일 예상매출/추천메뉴 산출.
- 재학습 시: 실시간 누적이 충분해지면 `rt_pay_amt` 를 **보조 타깃/피처**로 추가해
  추정매출(합성)의 한계를 실거래 신호로 보정 → 진짜 다이나믹 모델로 고도화.

## 실행
```bash
python scripts/spot_to_dong.py        # 매핑 테이블(최초 1회/갱신 시)
python scripts/realtime_to_dong.py    # 누적 realtime → 행정동 일자 집계
```
