# 7조 푸드트럭 DSS — 모델링 가이드 (v1.0)

> 데이터를 모았다고 곧장 XGBoost를 돌리지 마세요. 좋은 ML 모델은 **"무엇을 예측하는가(Y)"** 와 **"어떻게 평가하는가"** 를 먼저 합의한 뒤에 만들어집니다. 이 문서는 Y 정의부터 모델 비교·해석까지의 전체 의사결정 프레임워크를 정리합니다.

---

## 0. 의사결정 프레임워크 — 10단계

```
[Step 1] Y(타겟) 정의                 ← 가장 먼저, 팀 합의 필수
[Step 2] 평가 지표 결정               ← Y와 짝을 이룸
[Step 3] Train/Val/Test 분할 전략     ← 시간 기반 필수
[Step 4] Baseline 모델 (Linear/평균)  ← 비교 기준선
[Step 5] Feature Engineering          ← 14종 → 60~100개 피처
[Step 6] Feature Selection            ← 3단계 필터로 30~50개
[Step 7] XGBoost (Stage 1)            ← 본 모델 1
[Step 8] Neural Network (Stage 2)     ← 본 모델 2 (조건부)
[Step 9] GNN (Stage 3, 옵션)          ← 본 모델 3 (조건부)
[Step 10] SHAP 해석 + 메뉴 추천 모듈   ← 산출물
```

원칙: **모든 단계에서 baseline과 비교**. baseline 대비 의미 있는 개선이 없으면 그 단계를 버리는 게 맞습니다.

## 1. Y(타겟) 정의 — 가장 먼저, 가장 중요

### 후보 Y 3가지

| 후보 | 정의 | 장점 | 단점 |
|---|---|---|---|
| **Y1: log(매출액)** | log(분기별 푸드트럭 적합 업종 합 매출) | 정보 풍부, 회귀의 표준 | 절대값 해석 어려움 |
| **Y2: 매출 활성도 분위수** | 행정동별 매출을 1~10 분위로 변환 | 비즈니스 해석 직관적 | 정보 손실 |
| **Y3: 전기 대비 증감률** | (현재매출 − 전기매출) / 전기매출 | 동적 변화 포착 | Lag 의존도 높음, noise 큼 |

### 권장: Y1을 메인, Y2를 보조 지표

```python
# Y1: 푸드트럭 적합 업종만 필터링한 매출 합 → log 변환
FT_CATEGORIES = [
    "분식", "떡/한과", "커피/음료", "패스트푸드",
    "베이커리/도넛", "일식/회/초밥", "양식/이태리음식",
    "치킨/통닭", "한식음식점", "중식음식점"
]
# 푸드트럭이 실제 경쟁/대체할 수 있는 즉시소비/테이크아웃 업종으로 한정
panel["sales_ft"] = sales.query("category in @FT_CATEGORIES") \
                         .groupby(["adstr_cd", "yyqu"])["sales_amt"].sum()
panel["y_log_sales"] = np.log1p(panel["sales_ft"])  # log(1+x)로 0 처리
```

### Y 변환을 안 하면 생기는 일

매출 데이터는 **롱테일 분포**(강남역 일부 행정동이 평균의 100배 이상)입니다. 변환 없이 회귀하면:
- MSE는 강남역 한두 곳의 오차에 지배됨
- 모델이 "매출 큰 곳"만 잘 맞히고 일반 행정동은 무시
- → **반드시 log 또는 분위수 변환**

## 2. 평가 지표 — Y와 짝짓기

### 회귀 (Y1)

| 지표 | 수식 | 언제 쓰는가 |
|---|---|---|
| **RMSE** | √(Σ(y−ŷ)² / n) | 큰 오차에 페널티 → 이상치 민감 |
| **MAE** | Σ|y−ŷ| / n | 평균 오차 직관 → 이상치 둔감 |
| **R²** | 1 − SS_res / SS_tot | 모델이 분산을 얼마나 설명하는가 (0~1) |
| **MAPE** | (1/n) Σ |y−ŷ|/y × 100% | "평균 X% 오차" 비즈니스 보고용 |

**권장 조합**: **R² (메인) + RMSE (이상치 점검) + MAPE (보고서용)**

### 추천 (메뉴 Top-K)

| 지표 | 의미 |
|---|---|
| **Recall@K** | Top-K 안에 정답이 들어간 비율 |
| **NDCG@K** | 정답이 얼마나 위에 위치했는가 (순위 가중) |
| **Hit Rate@K** | 정답 1개라도 맞췄는가 (추천 UX 가까움) |

K=3, 5, 10 모두 보고하기를 권장.

### 평가 지표 보고 시 함께 적을 것

- baseline 대비 개선폭 (절댓값과 %)
- val/test 두 셋에서 일관된지
- 실패 케이스 정성 분석 (어느 행정동·분기에서 가장 틀렸나)

## 3. Train/Val/Test 분할 — 시간 기반이 필수

### 절대 하면 안 되는 것: Random Split

시계열 데이터를 random으로 나누면 **미래 정보가 train에 새어들어가는(data leakage) 치명적 오류**가 발생합니다. 모델 성능은 좋아 보이지만 실서비스에서 박살납니다.

### 권장: 시간 기반 Holdout

```
2019Q1 ─── 2020Q4   →  Train (8 quarters, 67%)
2021Q1 ─── 2021Q2   →  Validation (2 quarters, 17%)
2021Q3 ─── 2021Q4   →  Test (2 quarters, 17%)
```

분기 라벨을 그대로 split 기준으로 사용:

```python
TRAIN_QU = [20191, 20192, 20193, 20194, 20201, 20202, 20203, 20204]
VAL_QU   = [20211, 20212]
TEST_QU  = [20213, 20214]

train = panel[panel["yyqu"].isin(TRAIN_QU)]
val   = panel[panel["yyqu"].isin(VAL_QU)]
test  = panel[panel["yyqu"].isin(TEST_QU)]
```

### 더 엄격한 옵션: Time Series Cross-Validation (Forward Chaining)

```
Fold 1: train [Q1~Q4]    val [Q5~Q6]
Fold 2: train [Q1~Q6]    val [Q7~Q8]
Fold 3: train [Q1~Q8]    val [Q9~Q10]
```

`sklearn.model_selection.TimeSeriesSplit` 사용. 본 프로젝트는 분기가 12개라 fold 3개 정도가 적정.

### 코로나 시점 처리

2020Q1~2020Q4는 매출 패턴이 극단적으로 뒤틀렸습니다.
- 옵션 A: 그대로 학습 (모델이 "이상치 분기"를 학습)
- 옵션 B: 학습에서 제외 (단, 2021도 후유증 분기일 수 있음)
- **권장: 옵션 A + `is_covid` 더미 변수 추가** — 모델에게 명시적으로 알려주기

## 4. Baseline 모델 — 비교 기준선

복잡한 모델을 만들기 전에 **반드시 단순 baseline부터** 만드세요.

| Baseline | 정의 | 어디서 쓰는가 |
|---|---|---|
| **Naive (전기 매출)** | ŷ = y_lag1 | "직전 분기와 동일하다고 예측" |
| **Naive (작년 동분기)** | ŷ = y_lag4 | "1년 전 동일 분기와 같다" — 계절성 |

XGBoost가 위 baseline을 못 이기면 **데이터/피처 자체에 문제가 있다는 신호**입니다. 모델을 더 복잡하게 만들기 전에 데이터 검증부터 하세요.

## 5. Feature Engineering — 14종을 어떻게 가공하는가

원본 컬럼을 그대로 넣지 말고, **도메인 지식 기반으로 의미 있는 피처를 만들어야** 모델 성능이 살아납니다.

### 카테고리별 권장 피처 (60~100개)

#### A. 매출/상권 lag (5~9번 출처)

```python
# 가장 강력한 단일 피처군
panel["sales_lag1"]  = panel.groupby("adstr_cd")["y_log_sales"].shift(1)
panel["sales_lag4"]  = panel.groupby("adstr_cd")["y_log_sales"].shift(4)  # 작년 동분기
panel["sales_roll4"] = panel.groupby("adstr_cd")["y_log_sales"].shift(1) \
                            .rolling(4, min_periods=1).mean()
panel["sales_growth"] = panel.groupby("adstr_cd")["y_log_sales"].pct_change(1)

# 업종 다양성 (Shannon entropy) — 다양한 업종이 있는 상권일수록 유동인구 풍부
def entropy(group):
    p = group["sales_amt"] / group["sales_amt"].sum()
    return -np.sum(p * np.log(p + 1e-9))
panel["category_diversity"] = sales.groupby(["adstr_cd","yyqu"]).apply(entropy)

# 점포 turnover (개폐업 비율)
panel["turnover"] = (n_open + n_close) / n_total
```

## 6. Feature Selection — 3단계 필터

피처 100개를 다 쓰면 noise + 과적합. 30~50개로 줄이는 게 일반적.

### Filter 1: 통계적 기준 (자동)

```python
# 1) 분산 거의 0인 피처 제거
from sklearn.feature_selection import VarianceThreshold
vt = VarianceThreshold(threshold=0.01)

# 2) 결측 30% 이상 제거 (또는 imputation)
missing_rate = train.isnull().mean()
drop_cols = missing_rate[missing_rate > 0.3].index

# 3) 상관관계 0.95 이상 쌍에서 하나만 (다중공선성)
corr = train[features].corr().abs()
upper = corr.where(np.triu(np.ones(corr.shape), k=1).astype(bool))
drop_corr = [c for c in upper.columns if any(upper[c] > 0.95)]
```

### Filter 2: 모델 기반

```python
# XGBoost feature importance — 하위 20% 제거 후보
import xgboost as xgb
m = xgb.XGBRegressor().fit(X_train, y_train)
importance = pd.Series(m.feature_importances_, index=X_train.columns).sort_values()
drop_low_imp = importance.head(int(len(importance)*0.2)).index

# Permutation Importance — validation에서 음수/0 제거
from sklearn.inspection import permutation_importance
perm = permutation_importance(m, X_val, y_val, n_repeats=10, random_state=42)
drop_neg = X_val.columns[perm.importances_mean <= 0]

# SHAP 기반 selection
import shap
expl = shap.TreeExplainer(m)
shap_vals = expl.shap_values(X_val)
mean_abs_shap = np.abs(shap_vals).mean(axis=0)
```

### Filter 3: 도메인 기반 (수동, 가장 중요)

다음 질문을 던지며 한 번씩 점검:
- **이 피처를 비즈니스 보고서에 쓸 수 있는가?** (예: "y_log_sales_lag1_div_by_lag4_minus_one"은 No)
- **푸드트럭 사업자가 직관적으로 이해할 수 있는가?**
- **데이터 출처가 신뢰할 만한가?** (정부 공인 vs 크롤링)
- **계산 비용이 매출 예측 가치를 정당화하는가?**

권장: **30~50개로 압축 + data_dictionary.md에 한글 설명 첨부**

## 7. 모델 적용 — Stage별 가이드

### Stage 1: XGBoost — 무조건 시작점, 30분 안에 baseline

#### 핵심 하이퍼파라미터 (검증된 시작값)

```python
import xgboost as xgb

model = xgb.XGBRegressor(
    n_estimators=1000,        # early_stopping으로 자동 조절
    max_depth=6,              # 5~7 권장 (행정동 패널 데이터 기준)
    learning_rate=0.05,       # 작게 + n_estimators 크게
    subsample=0.8,            # 행 샘플링 (overfitting 방지)
    colsample_bytree=0.7,     # 컬럼 샘플링
    reg_alpha=0.1,            # L1
    reg_lambda=1.0,           # L2
    random_state=42,
    objective="reg:squarederror",
    eval_metric=["rmse", "mae"],
)

model.fit(
    X_train, y_train,
    eval_set=[(X_val, y_val)],
    early_stopping_rounds=50,
    verbose=100,
)

# 학습 후 best_iteration 확인 — 보통 200~500 사이
print(f"Best iteration: {model.best_iteration}")
```

#### 튜닝 우선순위 (시간 절약)

1. `max_depth` (5, 6, 7) — 가장 영향 큼
2. `learning_rate` × `n_estimators` (0.05/1000 vs 0.1/500)
3. `min_child_weight` (1, 5, 10) — 작은 표본에서 중요
4. `subsample`, `colsample_bytree` (0.7~0.9)

`optuna`로 100회 trial 정도면 충분 (5,088 obs는 작아서 튜닝 빠름).

### Stage 2: Neural Network — XGBoost 결과 보고 결정

**진행 조건**: XGBoost RMSE 대비 NN이 5% 이상 개선 가능성이 있을 때만.

5,088 obs는 NN에 작은 표본이라, **categorical embedding의 가치**가 핵심 진입점입니다.

```python
import torch
import torch.nn as nn

class FoodTruckMLP(nn.Module):
    def __init__(self, n_dong=424, n_sigungu=25, n_numeric=40,
                 emb_dim=16, hidden=128, dropout=0.3):
        super().__init__()
        self.emb_dong = nn.Embedding(n_dong, emb_dim)
        self.emb_gu   = nn.Embedding(n_sigungu, 8)
        self.emb_q    = nn.Embedding(4, 4)

        in_dim = emb_dim + 8 + 4 + n_numeric
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden), nn.BatchNorm1d(hidden),
            nn.ReLU(), nn.Dropout(dropout),
            nn.Linear(hidden, hidden//2), nn.BatchNorm1d(hidden//2),
            nn.ReLU(), nn.Dropout(dropout),
            nn.Linear(hidden//2, 1)
        )

    def forward(self, dong, gu, q, numeric):
        x = torch.cat([
            self.emb_dong(dong), self.emb_gu(gu), self.emb_q(q), numeric
        ], dim=1)
        return self.net(x).squeeze(-1)

# 학습 시 권장
# - optimizer: AdamW(lr=1e-3, weight_decay=1e-4)
# - scheduler: CosineAnnealingLR or ReduceLROnPlateau
# - loss: MSELoss (또는 HuberLoss for robustness)
# - epochs: 100 (early stopping patience=10)
# - batch: 256
```

#### NN의 가치 (성능 외)

- 행정동 임베딩에서 **유사 상권 자동 군집화** → t-SNE로 시각화 가능
- "강남역과 가장 유사한 행정동 Top-5" 같은 부수 분석 가능
- 본 프로젝트의 **방법론적 기여 포인트**

#### 그래프 구축

```python
import torch
from torch_geometric.data import Data
from torch_geometric.nn import SAGEConv

# 노드: 424개 행정동
# 노드 피처: Stage 1/2와 동일한 numerical features
# 엣지: 행정동 i ↔ j 간 대중교통 이동량 (OD matrix)

edge_index = torch.tensor(od_pairs.T, dtype=torch.long)   # [2, num_edges]
edge_weight = torch.tensor(od_volumes, dtype=torch.float)
x = torch.tensor(numeric_features, dtype=torch.float)     # [424, n_features]
y = torch.tensor(targets, dtype=torch.float)              # [424]

data = Data(x=x, edge_index=edge_index, edge_attr=edge_weight, y=y)

class GraphSAGEModel(nn.Module):
    def __init__(self, in_dim, hidden=64, out_dim=1):
        super().__init__()
        self.conv1 = SAGEConv(in_dim, hidden, aggr="mean")
        self.conv2 = SAGEConv(hidden, hidden, aggr="mean")
        self.lin = nn.Linear(hidden, out_dim)

    def forward(self, x, edge_index):
        x = torch.relu(self.conv1(x, edge_index))
        x = torch.relu(self.conv2(x, edge_index))
        return self.lin(x).squeeze(-1)
```

#### GNN 학습의 함정

- 분기마다 그래프를 새로 만들 것인지, 한 그래프로 통일할지 결정 필요
- 5,088 obs를 노드(424) × 분기(12)로 펼치면 작아서 over-smoothing 위험
- 학습 안정성이 떨어지면 GCN 대신 GAT, 또는 baseline에 만족하는 게 합리적

```python
# 1) (행정동×분기) × 업종 매출 비율 매트릭스
matrix = sales.pivot_table(index=["adstr_cd","yyqu"],
                           columns="category",

from sklearn.decomposition import NMF
nmf = NMF(n_components=10, random_state=42)
W = nmf.fit_transform(matrix)  # 행정동×분기 임베딩
H = nmf.components_            # 업종 임베딩

# 3) 추천 점수 = (수요 점수) × (수요/공급 갭) × (성공률)
demand_score = predicted_sales_for_category(adstr, yyqu, cat)

top_k = final_score.nlargest(K)
```

## 12. 자주 빠지는 함정 — 체크리스트

| 함정 | 회피법 |
|---|---|
| Random split → data leakage | 시간 기반 split (TRAIN_QU, VAL_QU, TEST_QU) |
| Y 변환(log) 누락 → outlier에 휘둘림 | log1p 또는 분위수 변환 |
| Lag feature를 만들 때 미래 정보 사용 | `groupby().shift()` 후 첫 분기는 제거 |
| target encoding을 train+val 합쳐서 fit | train으로만 fit → val/test에 transform |
| One-hot으로 차원 폭발 (행정동 424 → 424컬럼) | target encoding (XGBoost) 또는 embedding (NN) |
| Train RMSE만 보고 만족 | val/test 차이 (overfitting gap) 모니터링 |
| 코로나 분기를 무시 | `is_covid` 더미 추가 또는 별도 분석 |
| Feature Importance를 인과로 해석 | SHAP + 도메인 검증 |
| 모든 모델을 다 만들겠다는 욕심 | XGBoost를 끝까지 튜닝하는 게 NN 흉내내기보다 나음 |
| 메뉴 추천을 매출 예측과 같은 파이프에 욱여넣음 | 별도 모듈로 분리 |
