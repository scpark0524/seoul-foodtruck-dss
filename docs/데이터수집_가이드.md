# 7조 푸드트럭 DSS — 데이터 수집 가이드 (v1.0)

> 본 문서는 14종 공공데이터를 수집해 `행정동(424) × 분기(12) ≈ 5,088 obs` 패널을 구축하기 위한 실전 가이드입니다.
> 모든 데이터는 4개 공공 소스에서 무료로 확보 가능하며, API 호출 패턴이 비슷한 것들을 묶어 한 번에 처리하는 방식이 효율적입니다.

---

## 0. 전체 수집 전략 한눈에

```
[Step 1] API 키 4종 발급 (반드시 가장 먼저)
    ├─ 서울 열린데이터광장 인증키
    ├─ 공공데이터포털 일반인증키 (Encoding/Decoding)
    ├─ 상권분석서비스 인증키 (별도)
    └─ KOSIS Open API 키 (선택)

[Step 2] 분석 단위 표준화
    ├─ 공간키: 행정동 코드 10자리 (행정안전부 표준) — 424개
    └─ 시간키: 기준분기 YYYYQ (예: 20231 = 2023년 1분기) — 12개

[Step 3] 14종 데이터 병렬 수집 (카테고리별 분담 권장)
    ├─ 매출 5종 (5~9번): 상권분석서비스 API — 1명이 일괄
    ├─ 수요 2종 (1, 2번): 생활인구 + 인구주택총조사 — 1명
    ├─ 교통 2종 (3, 4번): 지하철/버스 승하차 — 1명
    ├─ 시설 2종 (10, 11번): 상가업소 + 집객시설 — 1명
    └─ 환경/맥락 3종 (12~14번): 기상 + 대기질 + 공휴일

[Step 4] 행정동 단위 결합
    ├─ 점/POI → 행정동: 공간조인 (geopandas sjoin)
    └─ 점 데이터(교통) → 반경 500m area-weighted allocation

[Step 5] processed/ 디렉토리에 통합 패널 데이터 저장
```

## 1. 사전 준비 — API 키 발급 체크리스트

### ① 서울 열린데이터광장 (data.seoul.go.kr) — 가장 자주 씀

1. https://data.seoul.go.kr 접속 → 회원가입
2. 마이페이지 → 인증키 신청 (개발 계정/운영 계정)
3. 발급 즉시 사용 가능, 일일 호출 제한 1,000건 (서비스별 상이)
4. **이 키 1개로 다음을 모두 호출**: 생활인구, 추정매출, 상권변화지표, 점포수/개폐업률, 소득소비, 연령대별 매출비율, 집객시설, 일부 교통 데이터

**호출 URL 패턴 (공통)**

```
http://openapi.seoul.go.kr:8088/{KEY}/{TYPE}/{SERVICE}/{START}/{END}/{ARG1}/{ARG2}...
```

- `{KEY}`: 인증키
- `{TYPE}`: `json` 또는 `xml`
- `{SERVICE}`: 서비스명 (예: `VwsmSignguStorW`, `VwsmAdstrdSelngW`)
- `{START}~{END}`: 페이지 인덱스 (1~1000 등)

### ② 공공데이터포털 (data.go.kr)

1. https://www.data.go.kr 접속 → 회원가입
2. 검색 → 원하는 API 클릭 → "활용신청" → 보통 즉시 승인
3. 마이페이지 → 활용 → 키 확인 (Encoding 키, Decoding 키 두 종류)
   - **requests 라이브러리에서 `params=`로 넘길 때는 Decoding 키, URL에 직접 박을 때는 Encoding 키**
4. **여기서 받을 데이터**: 기상 단기예보, 대기질, 공휴일 정보, 일부 교통 데이터

### ③ 서울시 상권분석서비스 (golmok.seoul.go.kr) — 핵심

1. https://golmok.seoul.go.kr 접속 → 회원가입
2. 좌측 메뉴: Open API → 인증키 신청
3. **단, 위 ① 서울 열린데이터광장 인증키로도 상권분석 데이터를 호출 가능** — 두 시스템이 통합되어 있어 ①번 키 우선
4. 핵심 서비스 (4종 상권으로 분리)
   - 골목상권 (`VwsmAdstrdSelngW`)
   - 발달상권 (`VwsmTrdarSelngW`)
   - 관광특구 (`VwsmTrtarSelngW`)
   - 전통시장 (`VwsmMrktSelngW`)

### ④ KOSIS / SGIS (통계청) — 인구주택총조사

1. KOSIS Open API: https://kosis.kr/openapi/index/index.jsp 회원가입 → 키 발급
2. 또는 SGIS: https://sgis.kostat.go.kr/developer/ — 공간 통계용 API
3. 인구주택총조사는 KOSIS API의 `KOSIS-110` 통계표 ID 등을 사용

### ⑤ (선택) 소상공인 상가업소 정보 — sg.sbiz.or.kr

- 별도 키 없이 분기별 전체 CSV 다운로드 가능 (300MB 내외)
- https://sg.sbiz.or.kr → 상권정보 → 상가업소 정보 → 다운로드

### 공간키: 행정동 코드 10자리

- 표준: **행정안전부 행정동 코드** (10자리, 예: `1168051000` = 강남구 역삼1동)

**행정동 매핑 마스터 파일 만들기 (필수 선행 작업)**

```python
# scripts/build_dong_master.py

# 또는 서울 열린데이터광장: "서울시 행정동 코드"
```

마스터 컬럼 권장: `[adstr_cd, sigungu, sigungu_cd, dong_name, lat, lng, area_km2]`

### 시간키: 기준분기 (YYYYQ)

- 형식: `20191`, `20192`, `20193`, `20194`, `20201`, ..., `20214` → 12개 분기
- 분기 정의: 1분기=1~3월, 2분기=4~6월, 3분기=7~9월, 4분기=10~12월
- **상권분석 데이터의 STDR_YYQU_CD 컬럼이 곧 이 형식**

**날짜→분기 변환**

```python
def to_yyqu(date):
    return int(f"{date.year}{(date.month - 1) // 3 + 1}")
```

### 결합 키 = (adstr_cd, yyqu)

모든 14종 데이터는 최종적으로 이 두 컬럼을 가진 형태로 정규화합니다.

## 3. 14종 데이터별 수집 가이드

### 카테고리 A. 매출/상권 (5종, 5~9번) — 한 번에 일괄 처리

**공통 사항**
- 출처: 서울 열린데이터광장 + 상권분석서비스 (동일 인증키)
- 단위: 행정동(또는 상권) × 분기
- 가용 기간: 2017~2023년 (대략) — **본 프로젝트의 12분기 정의는 여기서 결정됨**

| 번호 | 데이터 | 서비스명 (예시) |
|---|---|---|
| 5 | 추정매출 | `VwsmAdstrdSelngW` (행정동), `VwsmTrdarSelngW` (발달상권) |
| 6 | 상권변화지표 | `VwsmAdstrdChgArea` (또는 `VwsmTrdarChgArea`) |
| 7 | 점포수/개폐업률 | `VwsmAdstrdSal` (점포 수), `OpenStor` (개폐업) |
| 8 | 소득·소비 수준 | `VwsmAdstrdIncmCnsm` |
| 9 | 연령대별 매출비율 | 추정매출 응답 안에 컬럼으로 포함 (`MAL_AGRDE_SELNG_RAT` 등) |

> ⚠️ **서비스명은 서울 열린데이터광장 검색창에서 정확한 최신 명을 확인할 것**. 위 명칭은 일반적 패턴 예시이며, 시스템 업데이트로 바뀔 수 있습니다.

**호출 샘플 (Python)**

```python
import requests, time
import pandas as pd
from itertools import product

KEY = os.getenv("SEOUL_API_KEY")
BASE = "http://openapi.seoul.go.kr:8088"

def fetch_seoul_open(service, start=1, end=1000, *args):
    url = f"{BASE}/{KEY}/json/{service}/{start}/{end}/" + "/".join(map(str, args))
    r = requests.get(url, timeout=30)
    r.raise_for_status()
    js = r.json()
    rows = js.get(service, {}).get("row", [])
    return pd.DataFrame(rows)

# 예: 행정동별 추정매출 — 분기별로 페이징
all_dfs = []
for yyqu in [20191, 20192, ..., 20214]:
    page = 1
    while True:
        df = fetch_seoul_open("VwsmAdstrdSelngW", page, page+999, yyqu)
        if df.empty: break
        all_dfs.append(df)
        page += 1000
        time.sleep(0.3)  # rate limit 방어
sales = pd.concat(all_dfs, ignore_index=True)
sales.to_parquet("raw/05_sales_by_dong.parquet")
```

**컬럼 표준화 단계**

```python
# raw → processed
sales = sales.rename(columns={

    # ...
```

### 카테고리 C. 교통 (2종)

#### 3. 지하철 호선별 승하차

- 출처: 서울 열린데이터광장 (서비스명: `CardSubwayStatsNew` 등) 또는 서울교통공사 CSV
- 단위: **역(point) × 일자** — 행정동 단위 변환 필요
- 변환 절차:
  1. 역의 위경도(lat/lng) 확보 → 서울 지하철역 마스터 별도 다운
  2. 역 → 반경 500m 원 → 행정동 면적 가중 분배
  3. (역 일별 승하차) × (행정동별 면적 비율) → 행정동×일자 집계
  4. 일자→분기 평균

```python
import geopandas as gpd
from shapely.geometry import Point

stations = gpd.read_file("raw/03_subway_stations.geojson")
stations["geometry"] = stations.geometry.buffer(500)  # 500m 원 (CRS=5179 미터단위)
dong = gpd.read_file("raw/00_seoul_dong_polygons.geojson")  # 행정동 폴리곤

# overlay로 면적 계산
inter = gpd.overlay(stations, dong, how="intersection")
inter["area"] = inter.geometry.area
inter["weight"] = inter["area"] / inter.groupby("station_id")["area"].transform("sum")
# inter[station_id, adstr_cd, weight] 가중치 테이블 완성
```

## 6. 자주 빠지는 트랩과 팁

| 트랩 | 회피법 |
|---|---|
| 행정동 코드 자릿수가 데이터마다 다름 (5/8/10) | 모두 `astype(str).str.zfill(10)` 후 마스터와 join 검증 |
| 행정동 명 변경/통합 (2018~2023 사이 다수) | 마스터에 `effective_period` 컬럼 추가, 시점별 매핑 |
| API 일일 호출 제한 1,000~10,000건 | `time.sleep()` + 재시도 로직 + 결과를 즉시 parquet에 저장하여 재시작 가능하게 |
| 서비스 응답이 XML로 오는 경우 (`json` 미지원 서비스) | `xmltodict` 사용 또는 `dataType=XML`로 명시 후 파싱 |
| 매출 데이터 단위가 `만원` 또는 `원` 혼재 | data_dictionary.md에 명시, 표준화는 `processed/`로 가기 전 통일 |
| `serviceKey`에 `+`, `=`, `/` 포함 시 URL 인코딩 깨짐 | requests `params=` dict로 전달 (자동 인코딩), URL string에 직접 박지 말 것 |
| 생활인구 데이터 양이 너무 큼 (수백만 행) | DuckDB 또는 Polars 사용 권장. 분기 집계 후에만 pandas로 |
| 좌표계 혼재 (WGS84 / EPSG:5179 / EPSG:5181) | 공간조인 전에 반드시 `to_crs(5179)` (미터 단위)로 통일 |
| 추정매출의 라벨 정의 불명확 (`THSMON_SELNG_AMT` vs `MDWK_SELNG_AMT`) | 컬럼 정의서를 한 번 정리하고 팀 공유 |
| 분기별 데이터 부분 누락 (특정 분기 결측) | 결합 시 `outer join` → 결측 패턴 확인 → 실데이터 vs 보간 의사결정 |
